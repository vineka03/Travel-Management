📋 Software Requirements Specification

Travel Management System Core Features (srs.md)

1. Purpose & Scope

The purpose of the Travel Management System is to provide users (User1 and User2) with a simple system for managing travel activities, searching destinations, planning trips, booking hotels, selecting packages, and managing booking information.

2. Six Functional Requirements

  • FR-01 (User Login): Users can log in, switch accounts (User 1 / User 2), and manage their travel account profile.
  • FR-02 (Destination Search): Users can search and filter different travel destinations by name and category.
  • FR-03 (Trip Planning): Users can create, save, and manage custom day-by-day travel itineraries and budgets.
  • FR-04 (Hotel Booking): Users can search hotels, view amenities and star ratings, and book rooms.
  • FR-05 (Travel Package): Users can view and select all-inclusive holiday packages with meal and stay inclusions.
  • FR-06 (Booking Details): Users can view active bookings, update dates/guests, or cancel existing bookings.

3. Supabase PostgreSQL Database Architecture

The backend is connected to Supabase PostgreSQL with schema definitions, Row-Level Security (RLS) policies, and RESTful API routes:

  • users: User profiles, preferences, and multi-session switcher (FR-01)
  • destinations: Tourist spots, categories, durations, and ratings (FR-02)
  • trip_plans: Customized trip itineraries and budget calculations (FR-03)
  • hotels: Hotel listings, pricing per night, and amenities (FR-04)
  • packages: Holiday packages, inclusions, and discounts (FR-05)
  • bookings: Confirmed and cancelled user reservations (FR-06)
  • expenses: Trip category expenses and real-time ledger
